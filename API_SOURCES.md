## Reliability and provider limits

The public Nominatim policy limits heavy use and requires caching, attribution and at most one request per second. Public endpoints are suitable only for moderate, user-triggered use. The official [Overpass resource guidance](https://dev.overpass-api.de/overpass-doc/en/preface/commons.html) describes automatic load shedding, HTTP 429/504 responses and recommends planet/regional extracts or an owned instance for heavy workloads. ReisSlim's generator therefore uses bounded boxes, capped output groups, low concurrency, pacing, backoff and an external exact-query cache. Public Overpass and OSRM instances provide no production SLA; responses may be slow, incomplete, rate-limited or unavailable. Named POI/accommodation presence is evidence that a mapped object exists, not proof of opening hours, parking security, road access, price, inventory or bookability.

ReisSlim therefore uses bounded concurrency, cancellation, endpoint failover, partial results, source/freshness metadata and stale-if-error only for the identical normalized request. Provider failure must never substitute unrelated evidence or erase an already saved canonical plan. Generic suggestions keep the real route/base search anchor and are explicitly labelled rather than being rendered as fabricated venue coordinates.

Production scale should put provider-independent adapters behind an optional lightweight gateway or owned instances with shared caching, quotas, monitoring, privacy review and source-term enforcement. The static GitHub Pages PWA remains deployable without that gateway, but no shared commercial API key may be committed to or distributed in the browser.

## Reproducible catalogue build

Catalogue generation is deliberately split so public providers are never needed at runtime:

1. `npm run catalog:generate` rebuilds the GeoNames base packs.
2. `npm run catalog:overture:bulk:plan` creates exact, pinned place and transportation plans for all scale-derived important bases.
3. `npm run catalog:overture:bulk:fetch` obtains raw records and SHA-256 manifests in the external `REISSLIM_OVERTURE_CACHE`.
4. `npm run catalog:overture:bulk:apply` verifies those manifests and normalizes the records offline.
5. `npm run catalog:overture:bulk:merge` deterministically merges both evidence types into each flat country pack.
6. `npm run check:catalog:release` and `npm run catalog:quality-report` enforce and document the source-coverage gates.

For a release rebuild after the exact cache is complete, use `npm run catalog:rebuild`. It intentionally regenerates GeoNames first, reapplies the pinned Overture evidence and fails unless the complete release gates pass. Optional OSM enrichment remains available through the `catalog:osm:*` commands for an owned/configurable endpoint, but it is not required by the runtime or the pinned Overture release path. Set `REISSLIM_OVERPASS_ENDPOINT` and `REISSLIM_OVERPASS_CACHE` only when running that optional stage. See [CATALOG_DATA_NOTICE.md](CATALOG_DATA_NOTICE.md) before redistributing catalogue data.

The pinned Overture acquisition and normalization path is deliberately separate from the public Overpass cache. A complete source build has three stages: base-pack generation, pinned evidence acquisition/normalization, and deterministic merge plus release validation. With a complete exact external cache, generation and cache reapplication form a two-stage rebuild. Commands, identities and release gates are documented in [CATALOG_BUILD.md](CATALOG_BUILD.md). `npm run check:catalog:release` is intentionally stricter than ordinary development validation and must pass before enriched packs are published.
